# 深淵貓本分配器

獨立於 G27 的四人、四道具循序分配工具，不使用 G28 名稱。

使用網址：https://abyss-cat-allocator.web.app/

## 使用方法

1. 建立命名存檔，例如「0919」。填入四位隊員：寶寶 → 咩咩 → 爆肝 → 月。
2. 存檔建立後順序固定；當天組隊順序不同也不用改動。換隊員時另建存檔。
3. 每輪填入「證明、結晶(100)、結晶(300)、結晶(500)」數量；每種道具獨立輪流分配。
4. 可填寫寶物註解，例如「R8 改石 × 1，分給寶寶」。確認分配後自動保存。
5. 數量為 0 仍會記錄，該道具的順序不前進。四種都是 0 也能保存註解。
6. 關閉再開啟網站會接續上次存檔。左側可切換不同隊伍。
7. 歷史查詢可選日期區間，查看每日總量或逐輪分配與註解，每頁最多 30 筆。
8. 輸入錯誤時可撤回最近一輪。分配順序、累計及每日總量一起回復，再重新輸入。
9. 「複製分配」使用遊戲用短格式，例如 `0919(1) 證明：寶寶。 (100)：寶寶。`。省略 0 個道具、存檔名稱和寶物註解；註解仍完整保存在歷史內。多人使用頓號分隔，同人多份以 `×數量` 表示。
10. 輪次依每份存檔的紀錄日期計算。隔天從 `(1)` 開始，當天已有紀錄就接續編號；四種道具的輪替進度不重置。日期預設自動跟隨今天，跨午夜和重新回到分頁會更新，送出前也會再次確認日期。手動改成其他日期時維持指定日期，可按「使用今天」恢復自動模式。

本工具沒有最後回合、結束清算或尾數隨機。紀錄日期用於查詢；分配依實際存檔的先後順序前進。

## 本機存檔與備份

- 使用 IndexedDB，存檔之間彼此獨立。命名存檔相當於工具內的資料夾，不會自動在電腦建立實體資料夾。
- 開啟網站只讀取存檔摘要與最近一輪，歷史不會全部載入。每日摘要與歷史使用索引、每頁 30 筆按需查詢。
- 資料只在目前裝置、瀏覽器及網址中保存，不會上傳 Firebase 或 GitHub。其他人使用網站看不到你的存檔。
- 清除網站資料、使用無痕模式或更換瀏覽器可能失去本機存檔。請定期匯出 JSON 備份。
- 匯出包含目前選定存檔的所有輪次與註解；只有手動匯出時才一次讀取該存檔全部紀錄。
- 匯入會建立新的獨立存檔，不覆蓋原存檔，並依紀錄重算累計與下一位。
- 同時開啟多分頁會同步提示；儲存使用交易與版本檢查，避免不同分頁覆蓋進度。

## 開發與驗證

執行環境：Node.js 22 以上。正式網頁沒有第三方執行期相依套件。

```sh
npm install
npm test
npm start
```

本機網址為 `http://127.0.0.1:4178`。請使用本機伺服器，勿直接雙擊 HTML。

測試涵蓋獨立輪替、0 掉落、長期公平性、輸入驗證、交易失敗回復、多分頁競爭、日期分頁、撤回、備份及註解還原。

## 發布

推送到 `main` 後由 GitHub Actions 自動部署，流程是安裝相依套件 → `npm test` → `npm run build` → 部署。測試沒過就不會發布。也可以在 Actions 分頁手動執行「部署到 Firebase Hosting」。

需要在 repo 的 Settings → Secrets and variables → Actions 設定一個 secret `FIREBASE_SERVICE_ACCOUNT`，內容是 Firebase 服務帳戶金鑰的完整 JSON。金鑰只存在 GitHub secret，不進版本庫。

要在本機手動發布時：

```sh
npm run build
firebase deploy --only hosting --project g27-bead-allocator
```

發布設定只指向獨立 Hosting site `abyss-cat-allocator`，不修改 G27 原網站。`public/` 只含六個網頁檔案，不包含測試、備份或私人資料。
